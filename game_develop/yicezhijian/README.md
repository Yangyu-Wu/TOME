# 《一策之间》游戏客户端

> 2026-11-13 起，客户端目录统一为 `game_develop/yicezhijian/`，入口使用 `src/` 模块化架构。根目录 `game.js` 暂时保留为旧版客户端参考，不再由 `index.html` 加载。

《一策之间》是一款以三国武将招募、前后军编队和自动战斗为核心的浏览器游戏，目前处于开发阶段。无需安装引擎或构建工具，可使用 Chrome、Edge 或 Firefox 运行。

## 运行

在仓库根目录运行：

```bash
python3 -m http.server 8765 --directory game_develop/yicezhijian
```

然后打开 <http://localhost:8765>。当前入口使用 ES Modules，请通过本地 HTTP 服务运行；直接双击 `index.html` 可能被浏览器的模块安全策略阻止加载。

进度保存在当前浏览器的 `localStorage`。目录改名不改变存档键；使用相同浏览器和原有访问地址（包括主机名、端口）可继续读取已有存档。

当前入口默认使用测试环境：首次进入即拥有全部 59 名武将，不扣铜、不需要经过酒馆招募。部署页右侧“全武将名册”支持滚动、姓名/技能/职业搜索和魏蜀吴群雄筛选；先选择前军或后军阵位，再点击任意武将即可上阵，满位时会自动把原武将放回备战席。点击“撤下选中武将”可撤回，点击“一键演出阵容”会快速摆好四名演示武将。战斗中的刷兵与攻击节奏已针对测试阶段加速。

“一键演出阵容”包含吕布、关羽、诸葛亮和周瑜，进入战斗后可看到裂空冲击、青龙、七星和赤壁业火。已有存档会自动补齐缺少的武将，并保留原有星级、铜钱、波次和编队；测试环境的全武将收藏会写入原有 `yice-save-v1` 存档。右下角“音效：开/关”控制合成音效，浏览器会在首次点击后启用声音。

## 画面与战斗演出

- **粒子与光影：**火星、火焰余烬、烟雾、脚步扬尘、弹道拖尾、带重力和弹跳的碎片；技能采用叠加发光、半分辨率泛光、动态照明和冲击震屏。
- **场地破坏：**高能技能击碎木箱、拒马、树木和岩石，留下残骸、焦痕、裂纹和星阵印记。印记在本场战斗中持续保留，下一场重建场地；最多保留 72 处印记。
- **物理反馈：**空爆扩散冲击波、音爆锥环、击退、腾空与落地；龙卷会牵引敌人旋转，并卷起尘埃和碎片。被击败的小兵有短暂的翻倒消散动作。
- **专属大招：**关羽召出青龙斩击，周瑜以火凤引燃赤壁业火，诸葛亮排列北斗七星并逐颗砸向敌军。吕布裂空、赵云破音、张飞震吼、庞统/凌统龙卷、陆逊连营火、司马懿蚀月、马超踏空、张角雷罚、貂蝉闭月，共 13 位武将具有专属演出与机制。
- **完整施法过程：**全屏武将演出 → 技能投射/飞行 → 命中伤害与破坏 → 冲击余波。全屏演出串行播放，上一招的飞行和落点不会被下一段全屏动画盖住；同一场战斗的重复施法会缩短开场演出。
- **角色动画：**武将和小兵都有独立摆腿、摆臂、持械攻击、转向和移动起伏；武将增加披风摆动、羽饰、骑将马步，以及关羽的长髯青龙刀、周瑜/诸葛亮的扇饰。
- **阵营与入场：**我方战场模型、血条和姓名采用蓝色，敌方采用红色；普通敌兵不显示名字，精英和主将显示名字，体型逐级增大。四向援军从画面外走入，精英带脉冲光环与来袭提示；Boss 有 2.8 秒全屏登场，期间暂停战斗计时与攻击。
- **环境：**石板庭院、水池、树木、拒马与火炬；88 秒循环经历破晓、白昼、黄昏和深夜，光色、阴影方向、月色与火炬亮度连续变化。水面有动态波纹、天空反光、倒影以及技能/火场的光照反射。

场地、装备与音效主要由本地代码生成，基础人物与骨骼动画使用 Quaternius CC0 资源，地面 PBR 贴图使用本地缓存的 Poly Haven CC0 资源。针对 M5 MacBook Air 已接入 Three.js WebGL2 材质通道，使用 GLSL 光照、2K 颜色/法线贴图、各向异性过滤和动态 UV；若浏览器不提供 WebGL2，会自动保留 Canvas 渲染。

## 操作

- 当前测试环境：左侧选择前军/后军阵位，右侧点击已拥有武将，直接部署或替换；“撤下选中武将”返回收藏，“一键演出阵容”恢复吕布、关羽、诸葛亮、周瑜四将。
- 测试环境的备战席不受九格限制，完整名册始终可搜索浏览。
- 至少部署一名前军后才能出战。战斗全自动进行，前军移动、索敌、普攻和施放技能，后军按冷却提供支援。
- 每阵结束后进入胜负结算；返回营地时获得军资，胜利时按每 10 铜 1 铜计算利息，最多 5 铜。

### 常规规则与历史玩法约定

核心 `GameApp` 仍默认采用常规模式；Web 入口通过 `testMode: true` 显式开启全武将测试。以下酒馆招募和九格备战席属于常规规则，当前测试面板通过全武将名册直接选将：

- 休战幕间进入三国英雄酒馆：随机展示关羽、张飞、赵云、诸葛亮、马超、黄忠、周瑜、吕布、孙尚香、貂蝉等名将；新英雄先进入备战席
- 酒馆每轮展示五名英雄，刷新花费 2 金；英雄拥有不同招募价格、生命与攻击数值，并以刀盾/枪将/弓将定位参与战斗
- 幕间可循环调整前排/后排/备战席，最多 4 名出阵（前排 2、后排 2），只有出阵者参与战斗
- 休战界面采用上方酒馆卡池、中部帅帐前后军阵、下方备战席与军需操作区的布局，加入汉末军帐、酒旗、军需和铜钱视觉元素
- 休战界面进一步固定为四个上阵空位与九个备战空位；左侧常驻魏/蜀/吴、五虎上将、君主、卧龙凤雏、闭月羞花等羁绊，点击左侧“商店”标签后才展开纵向招募面板
- 阵位分为前军二席与后军二席，备战席固定九格；前军武将在场中自动战斗，后军技能栏显示在战场上方并按冷却释放技能
- 每场战斗目标时长为 80–120 秒。敌军约每 3–4 秒从东、南、西、北四个方向持续小批增援，难度提升会同时增加总人数、单批人数、生命、伤害、精英比例、远程比例和弓兵连射弹幕。
- 战斗改为完全自动进行，不再生成或操作玩家统领；前军武将独立移动、索敌和攻击，每名武将显示自己的姓名与生命条
- 后军武将显示在战场顶部，以技能进度条循环释放伤害或辅助支援
- 酒馆采用横向五张竖卡布局，卡片下方显示阵营/职业羁绊和铜钱价格；购买后该位置保留为空格，商店不会关闭，点击商店外区域才收起
- 至少部署一名前军后才能出战；战斗结束会进入明确的胜负结算页，领取基础军资和最多 5 铜利息后返回营地并刷新酒馆。
- 只部署一名英雄会触发“孤军被围”，即便是三星高费武将也无法单独通关，鼓励完整前后军编队。
- 测试阶段可在整备页直接选择普通战斗、遭遇战或 Boss 战；遭遇战提高刷兵与精英密度，Boss 战会生成高血量敌军主将并持续刷新援军。
- 当前出兵间隔约为 2–3 秒，敌我普攻速度均已提高；整体压力主要来自持续兵潮和弹幕叠加，而不是单次高伤秒杀。

## 游戏内容

- 全部游戏内容集中在中央战场，取消常驻侧栏、页眉和战报；
- 武将生命、星级和后军技能进度直接显示在战场中，顶部显示时间、难度、场上敌军与待增援数量；
- 80–120 秒自动战斗、分批增援的甲士/弓手/精英名将，以及随难度增加的弹幕压力；
- 自走棋式战后商店与部曲编组；
- 前军自动普攻与武将技能、后军周期支援；
- 程序绘制的三国武将造型：不同武将拥有稳定生成的盔甲、头盔、羽饰、武器、肤色与阵营配色；
- 战场包含石板、碎石、草丛、水池、岩石、树木、木箱、拒马和火炬，可被大招破坏并留下持续印记；
- 军师针对“弓手威胁”的记忆选择：接受提醒、先问/观察、或保持安静；
- 本地存档、战斗日志和最小研究轨迹可视化。
- 独立英雄模块：59 名三国武将，按 5/4/3/2/1 费分为 9/12/12/12/14 名，分别使用橙/紫/蓝/绿/灰稀有度。
- 三个同名同星武将自动合成高一星，最高三星；合成会优先保留前军、后军、备战席的上阵位置。
- 每名武将都有稳定生成的独特头像、盔甲、头盔、武器、羽饰和技能参数；战斗与界面共享同一英雄视觉数据。

## 当前开发阶段的限制

- 这是用于早期玩法讨论的灰盒，敌人 AI 和数值尚未平衡；
- 地形与特效采用 Canvas，英雄使用外部 CC0 人形底模与骨骼动画；当前人物仍共享通用男性底模，缺少独立高品质脸部、体型与服装，场地和人物也尚未统一深度遮挡；
- 记忆策略是确定性脚本，不接 LLM，也不代表最终算法；
- 目前战斗建议只针对弓手压力，不是完整战术 Agent；
- 字体使用系统中文字体；启动本地 HTTP 服务后无需联网即可游玩。

## 自动检查与画面验收

素材已按英雄模型、384×384 头像、小兵、青龙/火凤等特效、场地、水面和单个场景物体拆分，详见 [素材目录](src/assets/README.md)。战场默认输出 1920×1200，普通小兵与物件缩小 36%；青龙和火凤朝目标方向贯穿战场，沿途造成伤害后飞出屏幕，带转向、振翅和拖尾，同次飞行对每个敌人只命中一次。Canvas 为实时绘图，无视频编码码率设置。

在仓库根目录执行（需要本机安装 Chrome/Chromium，无需 npm）：

```bash
python3 game_develop/yicezhijian/tests/run-browser-checks.py
```

测试脚本自动启动临时 HTTP 服务，通过浏览器调试协议等待首页及所有测试页的实际完成结果，失败时返回非零状态码。使用真实时钟，避免虚拟时钟与持续高清动画互相阻塞；仅依赖 Python 标准库。`--chrome` 可指定浏览器路径。`--screenshots <目录>` 额外生成 20 张大招阶段、冲击、龙卷、晨昏水面、红蓝体型与敌军入场截图。`--real-time` 保留兼容，所有检查现在默认使用真实时钟。

使用真实时钟检查软件渲染压力（包含同步像素读回）：

```bash
python3 game_develop/yicezhijian/tests/run-browser-checks.py --only visual-effects.test.html --real-time
```

本地服务启动后也可打开 [画面验收页](tests/vfx-showcase.html)，切换青龙、业火、七星、龙卷、夜战和实时播放。自动测试覆盖专属大招时序、实际延迟伤害、七次落星、物理位移、破坏与留痕、光照/水面、59 名武将绘制、音效、粒子上限和完整页面流程。

# GPU 英雄动作预览

主页面默认启用透明 WebGL 英雄层，`index.html?gpuHeroes=0` 可切回 Canvas 英雄。它使用 `src/assets/heroes/models/quaternius-base-male/` 的带贴图 CC0 基础角色，加载 UAL2 的 43 个战斗动作及 UAL1 的两个原始快跑/冲刺循环，按速度调节步频；快跑与冲刺切换时保留步态相位。移动攻击混合下身移动与上身攻击，鞋底接触校正减少脚部悬空，披风使用 GPU 风动与同步阴影。阵营区分保留在身体、血条与标识上，装备、毛发及披风保留独立配色。地形、特效、血条和名字仍由 Canvas 绘制。GPU 层加载失败会自动回退到 Canvas 英雄，正式 3D 场景还需统一深度与遮挡。

关羽、吕布、赵云分别使用独立的偃月刀、方天画戟和长枪模型，具备刃根/刃尖拖尾锚点、金属材质、缠柄和不同轮廓。三人分别使用横扫、下劈和突刺控制曲线，双手 IK 保持握持、保留目标底模骨长。长柄攻击采用完整战斗周期，命中点统一触发扣血、受击与 GPU 金属火星；GPU 与 Canvas 从同一模拟时间读取进度。目标离开范围会挥空，眩晕/死亡/施法会取消待命中的攻击，普通轻微受击不中断已开始的动作。较慢的动作按单次伤害补偿基准持续输出，爆发和过量伤害仍需平衡。

全部源动画根据底模绑定姿态重定向，避免同名骨骼的不同骨长导致人物拉伸；贴身蒙皮内衬减少衣甲间裸露。近景可打开 [专属武器转台](tests/weapon-showcase.html)、[长柄动作检查页](tests/polearm-motion-showcase.html)和[实战命中慢放页](tests/impact-duel-showcase.html)，战场组合可打开 [GPU 英雄验收页](tests/gpu-hero-showcase.html)。这批程序化武器与动作尚缺雕刻烘焙、完整武术表演与刀刃几何碰撞，其余职业也尚未接入完整攻击周期，不能视为已达到 3A 资产标准。

该模式是当前设备的资产/动作验证路径，不是最终三国英雄模型；正式发布前需要把 CC0 人形重定向为各武将的生产模型。
